# 数据与维护

当前开发版实现；发布与验收结果以 IMPLEMENTATION_STATUS.md 为准。

## 目录

框架提供的 `plugin_data/astrbot_plugin_image_vote/` 是插件数据根：

| 内容 | 位置 | 保留规则 |
| --- | --- | --- |
| 场次、候选、最终票 | vote.db | 不自动删除；明确确认的 purge 删除对应场次 |
| 项目登记 | projects.json | 取消登记只删除登记项，不删原图 |
| 报告 | reports/ | output_root 留空时使用；自定义 output_root 保留，不自动搬迁 |
| 头像派生缓存 | avatar_cache/ | 默认 30 天；0 表示禁用过期清理 |
| 工作区缩略图 | cache/thumbnails/ | 默认 7 天、64 MB；按最近使用清理，容量可配置 |
| ZIP 下载临时包 | temp/image-vote-download-*/ | 下载结束清除；崩溃残留按安全规则清理 |
| 报告生成暂存 | output_root/.image-vote-*/ | 为原子替换留在同一文件系统；正常完成自动清除 |

不移动已有数据库或报告；修改 output_root 前应备份并确认已有报告路径。插件数据根以实际 AstrBot 配置为准，勿把表中的相对路径当作 NAS 宿主机绝对路径。

## 自动维护边界

启动及每小时执行维护。自动删除历史报告默认关闭；开启后只删有本插件 marker、超过保留期且未被读取/生成占用的报告。原图和投票记录保留。

临时目录必须同时满足：位于插件自己的扫描目录、有合法归属标记、超过一天、所属进程已结束。不会扫系统共享临时目录，也不删除无标记的旧目录。无法确认所属进程、PID 被复用或进程仍活着时保守保留；这些目录可能需要停机后人工核对清理。

头像只清理规范哈希命名的过期 WebP；工作区缩略图在每次写入和定时维护时按时间及字节容量清理。原图的路径、mtime、大小和缩略图尺寸共同参与缓存键，源文件改变会生成新缓存，旧缓存由保留策略清理。

## 内存边界

- 项目快照：最多 16 份，20 秒有效；同项目并发请求合并为一次扫描。
- 后端缩略图：最多 64 条内存缓存，解码一次一张；进入工作线程前限流，取消请求会等待其解码结束再释放名额。
- 前端缩略图：最多 60 条、60 秒有效，同一请求合并；关闭或切换视图后停止旧序列，忽略迟到的预检响应。
- 报告操作有会话级守卫，卸载停止定时维护与工作区任务。

上述限制不等于“绝无内存泄漏”或“磁盘永不增长”：单张超大图片仍需要解码内存，长时间大负载需专项压测；数据库和用户保留的报告是业务数据，不应伪装成缓存自动删除。SQLite 删除记录后通常复用空页，不保证立刻缩小文件；需要回收文件空间时应停机备份后维护，不在活动库上自动 VACUUM。
