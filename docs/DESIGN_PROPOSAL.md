# 总结报告与插件工作区设计提案

日期：2026-09-12。状态：供讨论的设计提案，尚未实施，不代表新增需求已全部确认。

本项目基线：0.10.0 / `44e0ce7`。结合 REQUIREMENTS §20、ROADMAP N1–N5，以及已完成的项目登记、结束通知、配置热读取与报告发群功能。

## 1. 产品定位与设计判断

总结报告是一份可以阅读、比较、回看的图片评选记录。插件工作区是一处帮助管理员把投票顺利跑完、找到报告、调整行为的操作界面。

两者共享颜色、字体、控件语言，信息密度不同：报告让图片和结果占主要空间，工作区让状态和操作清楚可见。

建议优先采用「静谧图册」方向：暖白底、深灰文字、少量紫色强调；用图片、留白和排版建立吸引力。深色模式使用炭灰底和较亮紫色。排名页提供紧凑列表；管理员页面保持中性、清晰，避免把报告的大图布局搬进表单。

## 3. 总结 HTML：三层阅读结构

导航只保留「概览 / 全部图片 / 按人查看」。统计口径放页尾可展开说明。默认打开概览；图片详情是侧栏或移动端全屏详情，不再增加顶层导航。

### 3.1 概览：先给结果，再给解释

从上到下：

1. **标题与场次。** 项目名、简短说明、日期、评分制；完整会话 ID 放详情，提前结束应明显标注「部分结果」。
2. **一行规模数据。** 已展示图片 / 总图片、参与人数、有效票数、每张平均票数。整体平均分降为次要数据，它不等于项目质量评分。
3. **高分图片。** 默认三张，展示完整图片、标题、平均分 / 满分、票数和排名；同分时保持现有排名规则。票数少的结果明确标记，不能通过装饰暗示“大家一致认可”。
4. **本轮看点。** 最多三条短结论：高分项、评分较分散项、票数覆盖情况。每条都能跳到相关图片或筛选结果。
5. **分歧与参与。** 左侧展示评分较分散的图片及分布；右侧按展示顺序画每图票数条形图。最多两张图表，不用堆叠仪表盘。
6. **阅读入口。** 查看全部图片、选择一位参与者。完整排名和所有头像不在概览重复铺开。

首屏目标：让读者在一个桌面视口内知道这是什么活动、规模多大、有哪些值得看的图片。AI 文本不能把图片挤到第二屏。

### 3.2 全部图片：同一组数据，两种密度

默认保留图片感，允许「图册 / 列表」切换。图册适合回看，列表适合比较；两者共享筛选、排序和选中状态。

列表每行：缩略图、名称、平均分 / 满分、票数、评分分布。序号与排名区分显示；完整文件名放详情。

工具栏：名称搜索、排序（排名 / 原始顺序 / 票数 / 分歧）、筛选（全部 / 少量评分 / 已展示未获票 / 未展示）。最低票数放高级筛选。显示「当前 8 / 19 张」和清除筛选入口。

不要默认过滤少票图片来悄悄改变正式排名。概览中的“较分散”等分析可以设置最低样本门槛，但要明确说明门槛。

详情布局：左侧完整图片与放大入口；右侧平均分、票数、分布与评分人列表。桌面可用右侧详情栏，手机采用全屏详情并保留返回位置。切换上一张、下一张沿用当前筛选后的顺序。

详情中的投票人按分值分组或排序，头像＋昵称＋分数即可；时间在展开后显示。点击参与者可跳到该人的完整选择，再返回原图片。

### 3.3 按人查看：回答“这个人喜欢哪些图”

桌面左侧为可搜索参与者列表，右侧为所选参与者；手机先选人再看详情。静态报告无法自动识别当前读者，入口应叫「选择参与者」，不冒充已登录的「我的评分」。

个人摘要：昵称、头像、已评张数 / 已展示张数、个人均分、常用分值。下方展示其高分图片和全部有效评分，支持按个人分数、图片顺序、最后更新时间排序。

可增加「与其他评分的差异」：某人的分数与同一张图其他投票人的均分比较。必须显示其他投票人的样本数；只有本人一票时不做比较。它反映本轮选择差异，不推断人格、审美水平或动机。

首版不做人气竞争式的“最佳评委”“品味大师”称号，不把不同评分习惯解释成能力高低。

## 4. 分析内容与口径

定义：P 为本轮至少投过一票的独立参与者数；S 为成功展示的候选图片数；V 为这些图片的最终有效票数。每人每图仅保留一条最终票。若历史数据包含未成功展示图片的票，应单独说明，不静默混入覆盖率。

| 内容 | 计算与展示规则 | 首版优先级 |
| --- | --- | --- |
| 平均分与票数 | 每图有效分数之和 / 票数；零票显示「暂无评分」；始终同时显示分制和票数 | 必需 |
| 排名 | 保留现有平均分降序、票数降序、原始序号升序；比较用原始精度，展示可四舍五入 | 必需 |
| 分值分布 | 1–5 等小量程用带标签横条；大于 10 个分值采用固定分组柱图并保留精确明细，避免 100 色图例 | 必需 |
| 分歧程度 | 复用总体标准差计算；单票标记「样本不足」，不展示成“共识最高”；概览建议至少 5 票才参与分歧排序，门槛可见 | 必需 |
| 图片评分覆盖 | 单图票数 / P；称「本轮参与者中的评分覆盖」，不能称群参与率或实际观看率 | 建议 |
| 每张平均票数 | V / S；S=0 时无数据。与当前以全部候选数为分母的字段明确区分，不悄悄改变旧字段含义 | 建议 |
| 个人评分覆盖 | 个人已评的成功展示图片数 / S；S=0 时无数据 | 建议 |
| 整体填写覆盖 | V / (P × S)，P 或 S 为 0 时无数据；不是群成员参与率，不放首屏大数字 | 次要 |
| 低票与零票 | 少量评分、已展示未获票、发送失败、提前结束未展示分别计数 | 必需 |
| 票数随展示顺序 | 横轴图片序号，纵轴最终票数；可发现分布变化，但不能据此断言“后半场疲劳” | 建议 |
| 个人与其他人的差异 | 本人分数减其他人的同图均分；展示共同候选和样本数量，默认至少有 4 位其他评分者才给文字结论 | 后续 |
| 完整改票时间线 | 现有 UPSERT 只保留首次创建与最近更新，不能恢复中间每次改票；需要新增事件数据 | 后续 |
| 跨场比较与人物合并 | 需要稳定跨 session 图片身份和明确分组；不能按文件名第一个连字符自动合并人物 | 后续 |

“评分较分散”比“最有争议”更准确：标准差描述结果分散，不能判断群里是否发生争论。少量票仅是描述性的样本提醒，不是统计显著性结论。

### AI 的内容职责

程序生成分数、排序、分布、样本提醒和事实摘要；AI 生成最多三条简短解释，可关联 candidate_id。推荐输出 headline / observations / candidate_ids；不让 AI 直接输出整页 HTML。

AI 未看图片，因此不能评论画风、服装或角色性格。可以说“这张图评分较分散”，不能说“红发造型引发分歧”。禁用、超时或结构不合法时显示程序生成的统计看点，页面仍完整。

## 5. 插件工作区：四个主入口

采用顶部导航「运行 / 项目 / 历史与报告 / 设置」。AstrBot 外层已经有导航，内页无需再占用一条宽大的品牌侧栏。只有项目详情与设置内部采用窄侧栏。

### 5.1 运行

以群为单位呈现活跃会话。卡片或紧凑行显示项目名、群、当前图片缩略图、成功发送 / 总数、当前图票数、参与人数和下一张倒计时。暂停时冻结倒计时，失败暂停应解释具体原因。

详情按「轮播 → 统计 → 报告」显示阶段。统计已完成但报告失败，应显示“投票已结束，报告生成失败”，提供重新生成报告；不只显示一个红色失败标签。

动作随状态变化：运行时暂停；暂停时继续；更多菜单内提前结束和取消。提前结束文案明确“停止后续发送，并按已收评分结算”；取消文案明确“保留已收评分，不自动生成报告”。

无运行任务时展示最近报告与「选择项目开始」，不放全为零的 KPI。Bridge 断开时保留最后状态并标记更新中断，禁止将旧数据当作实时数据操作。

### 5.2 项目

统一列出登记项目与目录项目，用轻量来源标签区分。每项展示名称、说明、最近预检结果与最近活动时间；管理员可以查看实际容器路径。

项目详情分为信息、图片预览和启动区。登记项目编辑名称、路径、说明、递归与间隔覆盖；目录项目可引导为其创建登记项以管理覆盖。取消登记与删除原图分开：本页面只提供取消登记。

路径输入支持直接粘贴绝对路径和“浏览目录”。浏览器从管理员明确配置的可浏览根目录开始，使用面包屑逐层选目录；宿主机未挂载目录不可见时提供清楚的映射说明。第一版只选目录，不扩展为文件上传、移动、删除工具。

预检展示图片数量、样本缩略图、首末顺序、预计耗时、输出可写情况。失败应落在具体字段：目录不存在、不可读、没有图片、输出不可写分别提示。

启动流程：选择项目 → 预检 → 选择目标机器人与群 → 查看本轮参数摘要 → 明确点击“开始投票”。准备过程不发群消息；提交后防重复启动。已有活跃会话的群直接显示占用原因。

本轮摘要要能解释来源，例如“间隔 15 秒 · 来自项目设置；评分 1–5 · 来自全局默认”。评分与间隔在开始后成为本轮快照。

### 5.3 历史与报告

一场投票一行，组合项目、群、时间、已展示数量、有效票数、投票状态和报告状态。首版合并历史会话与报告入口，避免让管理员来回找同一场数据。

报告状态至少区分：未生成、生成中、可查看、生成失败、已清理。操作按状态提供预览、下载、生成 / 重新生成、清理。

目录报告下载完整 ZIP；单文件报告下载 HTML。单文件超过上限回退后，按钮和提示必须跟随实际产物：“已改为目录报告，下载完整压缩包”。不能只下载 index.html 丢掉图片。

重导出默认复用既有 AI 摘要；单独勾选“重新生成 AI 总结”才调用模型，并提示会使用模型服务。重新生成先写新产物，成功后替换，避免失败覆盖可用报告。

清理确认列出目标场次、报告数量与占用空间，明确只清理派生报告、保留评分数据。清理后该行保留，可再次生成（源图仍可用时）。

### 5.4 设置：六组内容

左侧窄分组导航与搜索，右侧单栏表单。顶端常驻“有 3 项未保存修改 / 保存 / 放弃修改”；不要在每个字段外再套一层卡片。

| 组 | 内容与交互 |
| --- | --- |
| 投票规则 | 评分制快捷选项 1–4 / 1–5 / 1–10 / 自定义，发送间隔、最后等待、引用补票、每票确认；不可选择的重复投票策略显示为说明 |
| 项目与输出 | 输入根目录、报告根目录、默认递归；项目登记管理链接回项目页，不再复制一份登记表 |
| 报告与分享 | 目录 / 单文件、主题、图片质量、体积上限、是否包含参与者明细与头像、自动生成、群提醒、报告附件；压缩细节折叠到高级设置 |
| AI 总结 | 开关、已配置模型选择、留空跟随群、Top/Bottom 数量、提示词编辑与预览 |
| 使用权限 | 启动权限、群白名单；用可读的群名辅以群号，后端仍逐次验证权限 |
| 恢复与维护 | 重启行为、连续失败暂停、重试、报告保留与自动清理；默认只展开常用项 |

报告模式使用两块简洁单选描述：目录版“适合大项目，下载 ZIP”；单文件版“方便群文件分发，超限回退”。模式与发送开关存在依赖时就地说明，不让用户保存一个看似开启却永不生效的组合。

提示词编辑包含允许的变量清单、插入变量、恢复默认和“预览展开后的提示词”。预览只做本地替换，不调用 AI。“试生成”是独立显式动作。空模板使用默认值；不认识的变量在保存前指出。

### 保存与实际生效

保持同一份 AstrBot 配置：内置配置页和插件工作区使用同一 schema、同一后端保存与验证路径，避免两份配置互相覆盖。

保存返回持久化结果和读取后的实际值。页面区分：

- 本轮固定：评分范围、发送间隔等会话快照；提示“用于以后开始的投票”。
- 操作时读取：报告参数等；提示“下次生成报告时使用”。具体字段需与应用生命周期逐项核对。
- 系统级设置：路径、权限、恢复策略等；按真实实现说明生效时机，不承诺所有字段立即影响运行任务。

若另一个页面已更新配置，保存时提示冲突并保留当前草稿。没有变化时禁用保存；失败保留输入并定位错误。无需把磁盘 mtime 或 provider 内部标识展示给普通管理员。

## 6. 视觉规范

| 项目 | 报告 | 插件工作区 |
| --- | --- | --- |
| 画布 | 暖白 #F7F7F4，桌面内容宽约 1200px | 跟随 AstrBot 明暗主题，中性背景 |
| 强调色 | #6D5DFC；暗色建议 #B3A6FF | 同色系，仅用于主动作和选中状态 |
| 文字 | 深灰 #252831；次要文字 #687386 | 正文 14–16px，字段说明不小于 12px |
| 标题 | 项目名约 32–40px，章节 22–26px | 页面 24px，分组 18px |
| 圆角 | 图片与独立对象 10–12px | 控件 6–8px |
| 分隔 | 留白和细线优先，少量表面色区分 | 分组与行分隔，减少嵌套卡片 |
| 图片 | 保持完整主体；详情 contain，不强制所有原图裁为同一比例 | 缩略图辅助识别，不占据状态信息空间 |
| 数字 | 等宽数字，均分 / 满分与票数相邻 | 状态、时间和参数先保证易扫读 |

图片本身承担主要装饰作用。无需额外生成背景插画；概念图的角色图片仅为虚构示意，正式报告使用项目的派生图片。

色彩不能单独表达分数和状态：图表带标签，选中状态带文字 / 边框。分数色带沿同一套低到高顺序保持一致，零票与未展示使用独立灰色状态。

移动端先保证 390px 宽：指标两列，图册一列，表格转换紧凑条目，详情全屏，筛选可展开。保留缩放、键盘焦点、Esc 关闭与焦点返回，适配减少动画偏好。

## 7. 数据和实现边界

当前本项目报告只有候选聚合数据；投票人昵称等存在 votes 表中，尚未进入报告。需增加报告查询模型，避免让页面直接接触 SQLite 或让 report_generator 反过来承担业务聚合。

建议扩展报告数据包含：schema_version、session、metrics、candidates、participants、votes、insights、methodology。既有字段保持兼容；新字段缺失时旧报告仍可读取。

参与者使用报告内 ID 关联，而非把 QQ 号做公开 DOM ID。头像每位参与者下载一次，以报告内 ID 命名，失败用本地默认头像。公开分享版在生成阶段移除昵称、头像和逐人明细；只在 CSS 中隐藏不算移除。

现有离线约束继续成立：目录版与单文件版均无需运行后端。必要数据嵌入 HTML，避免 file:// 环境依赖 fetch(data.json)；data.json 同时保留为导出文件。资源无 CDN 依赖，主图按需载入，统计和基础列表无脚本仍能阅读。

建议增加的边界：

- 报告查询 / 聚合：从现有 store 生成报告数据，计算统计口径和样本提醒。
- 报告渲染：只将数据映射到模板、CSS、JS 与图片资源。
- Web 接口适配：桥接 AstrBot 身份、配置、目录浏览和应用服务，保持 main.py 的装配职责。
- 工作区前端：静态资源放 pages/image-vote；可以使用构建工具组织模块，运行时不依赖外网。首版无需引入参考插件完整的 React/Ant Design/FSD 体系。

网页控制必须调用现有 VoteApplication / ProjectService / SessionManager。群指令与网页操作共享群占用检查，后端验证目标群权限与路径；前端按钮禁用不能代替后端约束。

预览报告在受限容器中展示，不共享管理页上下文。昵称、文件名、描述和 AI 文本统一转义；桥接不可用时提示从 AstrBot 插件页打开，不能回退成未鉴权的公共管理 API。

## 8. 最小交付顺序与验收

1. 确认本提案的信息结构和一套视觉方向，明确报告默认分享范围。
2. 建立报告数据契约和查询聚合；用正常、零票、少票、部分完成、历史字段缺失的样本固定口径。
3. 实现概览、图片详情、按人查看、离线资源和明暗主题。支持 4 / 5 / 10 / 100 分制、长标题与头像失败。
4. 在目标 AstrBot 4.27.5 验证 bridge 的读、写、身份、主题与下载；先完成项目 / 历史报告 / 设置，再接运行控制。
5. 验收从“登记项目 → 预检 → 开始 → 暂停恢复 → 结束 → 下载报告 → 修改设置 → 再次导出”的完整路径，确认不会改动当前会话评分范围。

视觉验收覆盖桌面与 390px 手机；功能验收覆盖断网打开、无 CDN、搜索排序、详情返回、最低票数筛选、报告回退、配置未保存与冲突、断线状态、重复操作和重载恢复。

当前提案不包含跨场合并分析、完整改票事件流、主题市场、图片内容 AI 识别、全群成员画像。它们需要另外的数据基础或明确需求。

## 9. 仍需确认的产品偏好

建议默认报告用于原群内部，允许昵称 / 头像 / 最终评分明细；另提供不含个人信息的汇总分享版。若实际用途主要是公开发布，应反过来以汇总版为默认。

当前阶段只需确认默认分享范围和视觉方向；统计方法、入口命名、状态反馈等已有可实施建议，不必让用户逐项选择技术细节。
