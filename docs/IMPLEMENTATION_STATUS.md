## 二、当前能力

### 发送与计票

- 每人物可限制最多展示张数，并不重复随机抽选；本轮入选图片在创建时固定。可选开场及图片消息显示原始数量、抽选规则；规则和各人物原图数随场次保存，旧场次保持原文案。

- 扫描后按人物首次出现顺序分组，人物内部保持原顺序；同一人物图片连续发送（默认）或按组合并发送（每条默认最多 3 张，超出拆条）。
- 人物第一张成功发出即开放普通数字票；最后一张发完才等待完整人物间隔；最后一个人物使用最终等待时间，且不短于人物间隔。
- 新场次按消息原始接收时间和人物窗口归属普通数字票，引用本场图片归属该图人物；每人每人物一票，默认按真实消息顺序覆盖。旧场次保留原来的当前人物路由。
- 连续发送失败达到阈值自动暂停并在群里提示，`/vote resume` 继续；发送超时按失败处理。

### 报告

- 默认深色作品面板（可切浅色）：封面、奖牌高分卡、完整排名表、获票覆盖条、紧凑图册 / 人物列表切换、搜索与筛选。
- 离线 SVG 图表：评分分布柱状图、人物获票率环图、参与者评分分布与覆盖率；多人场次给出个人评分与本轮均分比较。
- 三种视图：概览 / 全部图片 / 按参与者查看；图片只作为人物素材，不单独计票或排名。
- 导出模式 `directory` 与 `single_html`；关闭参与者明细可生成汇总分享版；`report_image_policy` 默认每个人物只保留一张高清封面。
- `/vote send [短ID或session_id]` 可重发已生成报告：单文件发送 HTML，目录报告打包 ZIP，不重新生成报告或调用 AI。

### 插件工作区（Plugin Pages）

- 四个页面：运行 / 项目 / 历史与报告 / 设置。启动与预检、暂停恢复、目录登记与浏览、历史场次、报告下载与重新生成、清理与彻底删除、分组配置保存（含版本冲突）。
- 历史报告提供**下载**（单文件 HTML 或目录 ZIP）；报告预览已按用户要求移除，改为直接下载。
- 窄屏已验收：见下方验证方式表。

### 配置与元数据

- 配置写回同一份 AstrBotConfig，支持分组与扁平结构；评分范围 0–100、合并发送、超时、结束行为、AI 提示词模板等全部在配置页可编辑。
- `metadata.yaml` 含 `repo` / `astrbot_version` / `support_platforms` / `tags` 与 256px `logo.png`，具备提交插件市场的字段。

## 三、验证方式与最近结果

| 方式 | 命令 | 最近结果（2026-10-21） |
| --- | --- | --- |
| 单元测试 | `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -t .` | 182 项通过，无跳过 |
| 报告页检查 | `NODE_PATH=<playwright> node tools/check_report_ui.cjs` | PASS：排名、零分、转义、展开、搜索焦点、弹窗、来源、排序、主题、隐私与空态 |
| 面板检查 | `NODE_PATH=<playwright> node tools/check_panel_ui.cjs [--shots <dir>]` | PASS：明暗主题 54 组页面无横向溢出、无脚本错误 |
| 隔离 HTTP 验收 | `python tools/check_workspace.py --astrbot-source <AstrBot 检出>` | 0.13.12 重新运行 6 组断言通过；真实 SQLite/Pillow，群发送与模型为替身 |
| 大图处理 | `python tools/check_large_report.py` | 7 张 5000×5000 PNG，原图 SHA-256 未变（历史记录） |
| 真机场次 | NAS 实例（AstrBot 4.28.0 + NapCat） | 45 张 / 17 人物 / 46 票；报告生成、下载与重新导出均正常 |

两个浏览器检查都需要 Playwright：本机可 `npm install --prefix /tmp/pwcheck playwright` 后用 `NODE_PATH=/tmp/pwcheck/node_modules` 运行（脚本使用系统 Chrome，不下载浏览器）。

## 五、已知取舍

| 条目 | 现状 |
| --- | --- |
| 发送重试退避 | 实现为 2 / 4 / 6 秒（需求写 2 / 5 / 10） |
| 单文件超限回退通知 | 写日志与报告页说明，不回群消息 |
| AstrBot 限流队列 | 本版只等待已经进入插件的收票处理；尚未读取或等待上游限流队列，历史回扫属于后续能力 |
| 发图回执降级 | 元数据读取失败时保留成功发送结果并使用本机确认时间，同秒边界票不能保证完全恢复 |
| 项目内 `project.json` 的 `name` / `sort_mode` | 未实现；支持 `files` 顺序与 `characters` 映射，命中 `characters` 的图片同时使用 manifest 里的人物名作为展示标题 |
| 扫描忽略报告输出目录 | 未实现；`output_root` 放在项目目录内时会被扫到 |
| 报告重新导出 | 同一场次同一时间只允许一次导出；旧报告是静态快照，新样式不会自动回溯 |
